# CE transaction engine (experimental)
Development preview on PR #5. Default disabled; enabling requires a reload and a test world. Existing legacy CE accounting remains in use otherwise.

## Protocol
The active GM handles authenticated Foundry queries, re-resolves the actor/item/activity, checks ownership, restrictions and cost, and serializes requests by actor. A CE pool Item update contains both the integer/fractional debit and the persistent ledger record. One open reservation per actor is allowed; duplicate IDs in the retained ledger are rejected. The libWrapper MIXED adapter awaits reservation before calling D&D5e's async consume() method. D&D5e preActivityConsumption and postUseActivity are synchronous hooks, so async listeners cannot guarantee ordering. The adapter confirms native consumption on successful return; JJK post-use benefits check the committed context. Unknown/canceled/failed native consumption is retained for GM review instead of an unsafe automatic refund. GM resolution records a decision; it cannot undo external effects. Refund is of CE only (one-shot discount flags and other native resources require review). 200 closed entries retained; no claim of unlimited replay prevention. A GM switch during in-flight writes still requires testing.

## Compatibility and diagnostics
Do not directly patch native prototypes or replace Midi/DAE logic. Register via libWrapper only when enabled. D&D5e 6.1 source: https://github.com/foundryvtt/dnd5e/blob/6.1.x/module/documents/activity/mixin.mjs ; hook reference: https://github.com/foundryvtt/dnd5e/wiki/Hooks ; libWrapper: https://github.com/ruipin/fvtt-lib-wrapper . Existing Midi attack checks deduplicate by actual roll identity; DAE/native Burnout cleanup is serialized by the active GM. Other post-use listeners require a committed context when transactional CE is enabled. A missing adapter rejects managed native consumption rather than silently falling back. Adapter coverage for Midi-specific activity classes and overrides, nested/linked workflows and configuration clones must be established in real Foundry. The wrapper currently targets discoverable simple-identifier activity types; no assurance that every Midi activity type is wrapped.

GM console/API (test world):
`game.modules.get("jjk5e").api.ceDiagnostics(actor)` lists registered adapters, dependency presence and pending reservations.
`await game.modules.get("jjk5e").api.reconcileCE(actor, id, true)` refunds only after verifying no effect occurred; false confirms consumption instead. Never use either action automatically. Manual player CE changes use explicit GM approval in experimental mode. Rest is blocked while unresolved reservations are visible. Direct actor/item editing by owners, native pool resets, cross-document effects, external module workflows, automatic recovery, and cancellation timing are not guaranteed atomic; validate with two clients before enabling. Quick Recovery now uses the Strategist's separate native item uses; CE restoration requires recorded positive native uses-spent delta. Legacy copies recognized by activity ID/name, update from compendium recommended.

## Acceptance matrix
- Real Foundry 14.370, D&D5e 6.1.1, Midi-QOL 14.7.1, DAE 14.6.10, libWrapper; verify compatibility ranges against installed manifests.
- GM + two player clients: simultaneous same-actor casts, insufficient CE, duplicate query, canceled dialog, native resource failure, successful attack/save/damage/heal/utility, paid domain opening and reaction, linked activity, OverTime, multi-target attack, GM reconnect, long rest, direct CE edit, fractional cost.
- Verify damage and DAE effects occur only after confirmed payment, no double applications or recovery, no native refund discrepancy, and no wrapper conflicts. Repeat with legacy setting disabled. Existing automated tests use an in-memory mock, not this environment.
