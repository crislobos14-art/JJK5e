# Automation hardening — development increment
Baseline: 1.83.0 development branch; no production release or live Foundry certification.

## Action economy
- Native D&D5e activity and Midi-QOL action/bonus data remain authoritative for ordinary actions. JJK adds a client-local per-combat-turn ledger, one explicit free action per own turn, and Full Turn checks for used action/bonus and recorded movement. The ledger is not yet GM-authoritative, persistent or multi-client certified.
- Foundry V14 documented preMoveToken/moveToken and passed/pending movement cost used for recorded movement checks. Player recorded cost-bearing movement after full turn is blocked; GM can adjudicate forced movement and teleports. Movement not represented in history, manual rolls, rewinds, extra turns, multiple bonus actions, object interactions and unusual movement need live tests/explicit exceptions.
- 11 bundled full-turn activities and 7 explicit free actions identified by stable activity IDs from their source descriptions (including Golden Hour, Seance, Ritual Dance, Inari, Boogie Woogie, Blood Edge and Wing King). The existing compendium's 2000 IQ feat has only a bonus-action activity and describes the full-turn alternative differently from the V6 general combat passage; no new automatic lesser action was invented. Explicit condition metadata can support a lesser full turn. Wing King multi-attack and Vengeful Spirit once-per-round behavior remain individual activity audits.
- Off-turn full turns blocked except a current domain reaction claim. Optional Additional Actions blocked when disabled. Existing Midi workflow/reaction ownership, native activity timing and domain authority remain live acceptance gates.
- Yearly Progression, Fight for your Life, Tough Trials and Object Soul grants now respect opt-in at execution; removing an existing trial or soul effect remains available to the GM.

## Short rest CE
Source: V6 Intricacies of Sorcery / Short Rest Regain: half maximum HD cap, 1 CE per HD.
- Native dnd5e.restCompleted opens an exchange; one batch per completed short rest, cap computed against actual available HD and CE deficit. Conservative UI policy: no exchange while combat is started; no automatic prompt or multiple partial exchanges.
- If transactionalCE enabled, non-active GM submits to existing GM authority route; otherwise same-client queue. Intent stored on actor flag shortRestExchange as review before one embedded Item batch, then exact field verification and committed record. Uncertain outcomes block CE usage/rest and require GM reconciliation. GM panel offers reconciliation when all current values match either the prior or expected values; mixed values must be manually corrected first. This is not a database-wide atomic transaction, and concurrent client/native modifications and restart recovery need live testing.
- Native Sorcerous Restoration and other rest hooks retained. Rest window lifetime after unrelated events, interrupted rests and multi-client authority need integration tests.

## Ten Shadows
Source: V6 Ten Shadows / Divine Dogs, Trial; Rules of Thumb shikigami.
- Active GM receives decision at HP crossing to 0 for recognized shikigami with unique linked token: recall with available reaction, confirm permanent loss (or alternative), or leave unresolved/ritual. Recall is recorded separately and cleared after long rest; it does not grant Totality eligibility. Existing summon entry points consult recall lock. GM panel can retry unresolved 0 HP adjudication.
- GM confirms visibility and tamed/ritual state. Reaction marker delegated to Midi where available. Native summon profile identity, two Divine Dogs, multi-token linked actors, taming, command economy, Totality and capacity still require dedicated engine. Direct GM overrides and summon timing are not certified.
