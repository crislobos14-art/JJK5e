# Engine hardening — roadmap 1.76.1–1.80.0 (development branch)
Source baseline main v1.76.0. This is an incremental development PR, not five released versions. Transactional CE remains disabled by default.

## CE stability and persistent recovery
- Receipts include actor UUID as well as item/activity identity. Two-phase protocol: reserve CE on the pool Item, then persist nativeStarted before permitting native consume. A repeated start is rejected; retrying commit of an already committed operation does not debit again.
- Recovery scans world actors and synthetic scene actors on ready, user connection, time update and every 30 s (active GM only). After 120 s, explicitly unstarted protocol-2 reservations can be refunded once; started/legacy records become review. No automatic refund if native execution could have occurred. One-shot reductions are consumed at start rather than reservation.
- Midi usage card receipt is stored in our own namespace and linked on the GM after checking author, actor, item, activity and receipt flag. A receipt may link to one card only. A link is audit evidence, not permission to replay a resumed workflow. Resumed workflows without verified live local context still fail closed. Test card association and actual timing inside Foundry. Native effects/actor flags and pool writes span multiple documents; do not promise global atomicity.

## Integration engine
- GM panel: JJK Integration Diagnostics, versions/presence, adapter coverage, duration authority and pending CE. Explicit confirmation/reimbursement after checking actual native results. API: integrationReport(), recoverCEWorld(), reconcileCE(actor,id,refund). Only active GM can settle.
- Existing Midi/DAE bridge remains experimental; off-canvas TokenDocumentSet targets are included for wards without replacing the set. Linked, concentration, summon and custom activity variants still need real acceptance testing. No automatic compatibility certification or new fallback guarantees.

## Selectable barriers (experimental)
GM opens Domain HUD and uses Create selectable barrier marker. Creates one linked NPC/Token marker on the circle edge, with barrier AC and HP. Select the marker, control an attacker, choose Attack selected barrier marker in the JJK panel. Uses the existing reviewed attack command (distance to ring, inside/outside, AC, dice, GM authority); normal native attacks against marker are intentionally blocked to avoid creature damage/effect double application. Syncs HP and removes marker on domain closure. This is not a continuous physical wall or native Midi-QOL damage integration. Test permissions, level assignment, document creation, collision, deletion and orphan recovery in a real world. Direct ordinary damage application to proxy must not be used.

## Antidomain features (V6)
Source: JJK 5e V.6, master Drive document 1eC8tEMHnupOuaX6At1X8JORz5iarNe6I-A7j2QzScrE, sections Falling Blossom Emotion, Hollow Wicker Basket, Simple Domain, Domain Refinement.
- Simple Domain costs 4 CE; 10 ft, one minute; independent barrier HP = 2 × proficiency × selected CE modifier. Migrated compendium activities are utility rather than temporary-HP heal; update existing actor copies from compendium. Anchor token movement/level/elevation invalidates protection. GM API simpleDomainAt(token), absorbSimpleDomain(effect,damage,eventId) serializes shared finite HP, idempotent area event, returns overflow. Custom domain profiles route damage through this barrier. Ordinary attacks/spells/Midi area overlap, full area damage routing and overlapping barriers still require explicit GM adjudication. Legacy temp HP effect remains manual rather than deleting unrelated temp HP.
- Falling Blossom defense: add action (5 CE) in addition to reaction (5 CE). Offensive action (4 CE) now prepares independent single-use readiness for 1 min; GM API claimFallingBlossomOffense(actor) consumes once. Actual incoming attack timing, reaction consumption, advantage/critical/necrotic melee attack require GM adjudication.
- Hollow Wicker Basket retains selected 15-ft allies, 4 CE, one minute; no additional upkeep invented. Verify reaction timing and native effects in Foundry.
- Domain Amplification maximum-output comparison helper: difference >=51 attacker stronger = normal; within 50 resistance; defender >=51 stronger immune. Not automatically wired to arbitrary offensive/defensive techniques, maximum-output workflow flags or Infinity. Celestial Body existing guaranteed-hit immunity preserved.
- Compendium metadata and revision stamps updated.

## Acceptance gates
Run repository CI (syntax, lint, stamps, tests, audits, compendium build). Before declaring compatibility or enabling transaction mode, test real Foundry 14.370 / dnd5e 6.1.1 / Midi-QOL 14.7.1 / DAE 14.6.10 with GM + two clients: canceled dialog, lost response before/after start, GM switch, card resume, linked/cast/summon, concentration, target sets on other levels/scenes, barrier proxy placement and teardown, simultaneous attacks, shared Simple Domain HP and movement, reaction ordering. The automated harness does not instantiate those modules. Do not publish or label full 1.80.0 implementation solely on mock results.
